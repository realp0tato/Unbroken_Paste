# ClipBridge 제품 요구사항 문서 · PRD v2

**한 줄 소개:** 한글↔워드 사이에서 평소처럼 복사·붙여넣기하면, AI가 내용의 구조를 판단하고 붙일 문서의 서식 규칙에 맞춰 다시 짜 넣어 주는 Windows 백그라운드 앱.

|---|---|
| 문서 버전 | v2.0 (v1.0 ClipBridge PRD + PasteFit 기획 통합) |
| 작성일 | 2026년 10월 30일 |
| 프로젝트 | ClipBridge — 대학 AX 해커톤 MVP |

| 범위 확정 사항 | 설정 화면, 비밀번호 입력란 확인, 사용자 앱 제외, 일시정지 기능 제외 |

## 1. 문제 정의

한국은 공공기관·학교가 한글을, 기업·해외 협업이 워드를 쓰는 이중 문서 환경이다. 학생과 실무자는 두 프로그램 사이에서 글과 표를 자주 옮기고, 그때마다 다음 수작업이 생긴다.

- 붙여넣기 선택지가 "원본 서식 유지" 아니면 "텍스트만"뿐이다. 원본 서식으로 붙이면 글꼴·줄간격·표가 깨지고, 텍스트로 붙이면 제목·목록 구조가 사라진다.
- 표는 원본 형식으로 붙이면 크게 깨져서, 엑셀이나 워드에 한 번 붙였다가 다시 복사하는 우회법을 쓴다. ([클리앙](https://www.clien.net/service/board/kin/16407581))
- 워드의 "1.1.1" 번호와 공문서의 "1. → 가. → 1) → 가)" 기호 체계가 달라 손으로 다시 매긴다.
- 한글 줄간격은 % 단위(기본 160%), 워드는 배수·pt 단위라 붙인 뒤 문단 간격이 어긋난다.

**해결하려는 문제는 '붙인 뒤 문서 규칙에 맞게 다시 고치는 반복 작업'이다.** 기존 기능은 서식을 옮기거나 버릴 뿐, 붙일 문서의 규칙에 맞춰 다시 짜 주지 않는다.

## 2. 제품 목표

### 2.1 핵심 가치

**"앱을 실행해 두고, 원래 하던 대로 복사·붙여넣기하면 붙일 문서의 양식대로 들어간다."**

사용자에게 변환 버튼, 모드 선택, 별도 업로드를 요구하지 않는다. 백그라운드 동작은 작은 오버레이로만 알려 준다.

### 2.2 MVP 목표

1. 워드 → 한글: 복사한 제목·본문·목록·표를 붙일 한글 문서의 규칙(글꼴, 크기, 줄간격, 공문서 기호 체계)에 맞춰 넣는다.
2. 한글 → 워드: 복사한 제목·본문·목록을 붙일 워드 문서의 스타일(제목 1/2, 본문, 목록 번호)에 맞춰 넣는다.
3. AI는 서식만으로 애매한 구조(굵은 한 줄이 소제목인지 강조인지, 목록 단계)를 판단한다. 글자 내용은 절대 바꾸지 않는다.
4. AI 맞춤이 실패하거나 늦으면, 이미 들어간 일반 붙여넣기 결과를 그대로 둔다.
5. 일반 텍스트 Markdown·TSV는 v1.0 기능대로 HTML 서식을 추가한다(기본 계층).
6. 복사 출처와 붙여넣기 대상, 맞춤 결과를 짧게 보여 주되 입력을 방해하지 않는다.

### 2.3 MVP에 포함하지 않는 것

- 비밀번호 입력란 검사, 사용자 앱 제외 설정, 일시정지, 상세 설정 화면.
- 로그인, 계정, 클라우드 동기화, 복사 기록 저장, 관리 대시보드.
- 글의 의미를 바꾸는 AI 재작성·요약·번역. AI는 구조 판단과 스타일 연결만 한다.
- 한글과 워드 간 문서 레이아웃·페이지 설정의 완전한 일치.
- 이미지·수식·차트·병합 셀·각주의 재구성.
- 같은 프로그램 안의 붙여넣기(워드→워드, 한글→한글) 맞춤.
- 구글 독스·노션·PPT 연동(확장 비전으로만 발표).
- macOS·Linux 지원. 한글 자동화가 Windows 전용이다.

## 3. 주요 사용자와 시나리오

| 사용자 | 수행하는 작업 | 원하는 결과 |
|---|---|---|
| 대학생 (1차 타깃) | 워드·구글 독스로 쓴 팀플 보고서를 학교 한글 양식에 옮김 | 양식 글꼴·기호 체계를 손으로 맞추는 시간 감소 |
| 공공기관 실무자 | 외부 워드 자료를 한글 공문서로 옮김 | 공문서 항목 기호·글꼴 규칙 자동 준수 |
| 기업 실무자 | 관공서 제출용 한글 문서와 사내 워드 문서를 함께 작성 | 양방향 이동 시 서식 오류 감소 |

### 대표 시나리오 A — 워드 보고서를 한글 양식에 (메인 시연)

사용자가 워드 보고서에서 "1. 연구 배경"부터 표까지 블록을 지정해 복사한다. 출처 아이콘(Word)이 잠깐 뜨고, ClipBridge는 백그라운드에서 AI로 구조를 미리 판단해 둔다. 학교 한글 양식에서 Ctrl+V를 누르면 먼저 평소대로 붙는다. 1초 안팎으로 같은 위치의 내용이 양식 규칙(함초롬바탕 10pt, 줄간격 160%, "1. → 가. → 1)" 기호)대로 바뀌고, `Word → 한글 · 양식에 맞춤` 오버레이가 뜬다.

### 대표 시나리오 B — 한글 공문서를 워드 보고서에 (반대 방향)

한글 공문서의 "가. / 1)" 항목을 복사해 워드 보고서에 붙인다. 붙인 내용이 워드 문서의 제목 2·목록 번호 스타일과 본문 글꼴로 바뀐다.

### 대표 시나리오 C — 원래 방식으로 계속 붙여넣기

이미지, 복잡한 Office 데이터, 지원하지 않는 앱 사이의 복사는 다시 쓰지 않는다. AI 맞춤 조건이 맞지 않으면 일반 붙여넣기 결과가 그대로 남는다.

### 대표 시나리오 D — Markdown 보고서 (안전망)

일반 텍스트로 복사한 Markdown을 워드·한글에 붙이면 v1.0 기능대로 제목·굵게·목록·표가 적용된다. AI 계층이 동작하지 않는 환경에서도 시연할 수 있는 경로다.

## 4. 사용자 경험

### 4.1 기본 흐름

```text
앱 실행
  → 창 없이 트레이에서 동작
  → 사용자가 한글/워드에서 글·표 복사
  → 출처 앱 아이콘 잠깐 표시
  → [백그라운드] 클립보드 HTML 파싱 → AI 구조 판단 → 결과 보관
  → 사용자가 대상 앱에서 Ctrl+V
  → 평소대로 즉시 붙여넣기 (키 입력은 막지 않음)
  → [백그라운드] 대상 문서 주변 서식 읽기 → 규칙 엔진으로 재조립
  → 사용자 추가 입력이 없으면 방금 붙인 내용을 맞춤 결과로 교체
  → "출처 → 대상 · 양식에 맞춤" 오버레이 후 사라짐
```

실행 이후 정상적인 복사·붙여넣기 과정에서 추가 클릭은 **0회**여야 한다. 종료는 트레이 메뉴의 `Quit ClipBridge` 한 항목으로 제공한다.

### 4.2 맞춤 결과 되돌리기

- 맞춤 직후 대상 앱에서 **Ctrl+Z 한 번**을 누르면 붙여넣기 이전 상태로 돌아간다. ClipBridge는 맞춤 작업을 실행 취소 한 단위로 묶는다.
- 원본 서식 그대로 붙이고 싶으면 대상 앱의 "선택하여 붙여넣기 / 골라 붙이기" 메뉴를 쓴다. ClipBridge는 이 경로를 가로채지 않는다.
- P1: 오버레이에 포커스를 빼앗지 않는 "원본으로" 동작을 추가하는 방법을 검증한다.

### 4.3 오버레이 요구사항

| 항목 | 요구사항 |
|---|---|
| 복사 표시 | 출처 앱 아이콘 및 짧은 앱 이름 |
| 붙여넣기 표시 | 출처 앱 아이콘 → 대상 앱 아이콘 + 상태 |
| 상태 문구 | `복사됨` · `구조 분석 중` · `양식에 맞춤` · `기본 붙여넣기 유지` 중 하나 |
| 위치 | 기본 모니터 오른쪽 아래, 작업 내용을 가리지 않는 위치 |
| 크기 | 약 450 × 88px 이내 |
| 표시 시간 | 기본 1.5초, 맞춤 완료 시 2초, 자동으로 사라짐 |
| 조작 | 확인·닫기 버튼 없이 자동 동작 |
| 포커스 | 대상 앱의 커서, 키보드 입력, IME 조합을 빼앗지 않음 |
| 아이콘 확보 실패 | 앱 이름과 문자 배지로 대체 |
| 출처 불명 | 추측하지 않고 'Unknown' 표시 |
| 내용 노출 | 복사한 본문이나 문서 제목을 표시하지 않음 |

실제 맞춤 교체를 확인하지 못했으면 `양식에 맞춤`이라고 표시하지 않는다.

### 4.4 예외 상황의 사용자 경험

- AI 판단이 붙여넣기 시점까지 끝나지 않으면 일반 붙여넣기 결과를 유지한다. 붙여넣기를 기다리게 하지 않는다.
- 붙여넣기 후 사용자가 바로 타이핑·클릭을 하면 맞춤 교체를 취소한다. 사용자가 쓴 내용을 덮어쓰지 않는다.
- 자동 재붙여넣기를 실행하지 않는다. 같은 내용이 두 번 들어가면 안 된다.
- 미지원 입력은 기본 붙여넣기를 사용한다. 복사한 데이터를 버리거나 빈 내용으로 바꾸지 않는다.

## 5. 동작 구조

### 5.1 두 계층

| 계층 | 조건 | 동작 | 상태 |
|---|---|---|---|
| ① 기본 계층 | 일반 텍스트 Markdown·TSV, 지원 대상 앱 | 클립보드에 없던 HTML 포맷만 추가(v1.0 그대로) | 구현됨 |
| ② AI 맞춤 계층 | 출처·대상이 한글↔워드 조합 | 일반 붙여넣기 후, 붙인 범위를 대상 문서 규칙에 맞춘 내용으로 교체 | 신규 |

두 계층은 독립적이다. ② 계층이 꺼지거나 실패해도 ① 계층과 일반 붙여넣기는 그대로 동작한다.

### 5.2 AI 맞춤 계층의 처리 단계

```text
[복사 시점 — 작업 스레드]
 1. 클립보드 HTML 파싱 → DocBlock 초안 (블록 단위 텍스트 + 서식 힌트)
 2. 규칙으로 확실한 블록은 바로 확정 (예: 워드 제목 스타일, 표)
 3. 애매한 블록만 묶어 LLM 1회 호출 → 구조 태그 JSON
 4. JSON 스키마 검증 + 내용 보존 검사 통과 시 보관

[붙여넣기 시점 — 키보드 훅은 관찰만]
 5. 훅: 대상 앱 식별, 붙여넣기 시각 기록 → 작업 스레드 깨움 → 키는 그대로 전달
 6. 대상 앱이 평소대로 붙여넣기
 7. 작업 스레드: 대상 문서 커서 주변 서식 읽기 → target_rules
 8. 규칙 엔진: DocBlock + target_rules → 대상 서식으로 재조립 (단위 환산, 기호 체계)
 9. 교체 조건 확인 → 실행 취소 한 단위로 "일반 붙여넣기 취소 + 맞춤 내용 삽입"
10. 오버레이 표시
```

AI 호출을 복사 시점에 미리 끝내므로, 붙여넣기 이후에는 문서 읽기와 규칙 계산만 남는다.

### 5.3 교체 안전 조건

아래 조건을 **모두** 만족할 때만 일반 붙여넣기 결과를 맞춤 결과로 바꾼다. 하나라도 어긋나면 아무것도 바꾸지 않는다.

1. 출처와 대상이 서로 다른 지원 앱(한글↔워드)이다.
2. 붙여넣기 시점의 클립보드 sequence가 AI 결과를 만든 복사의 sequence와 같다.
3. AI 결과가 스키마 검증과 내용 보존 검사를 통과했다.
4. Ctrl+V 이후 대상 앱에 다른 키보드·마우스 입력이 없다.
5. 붙여넣기로 바뀐 문서 범위를 확인했고, 그 범위의 텍스트가 복사한 텍스트와 일치한다.
6. Ctrl+V부터 교체까지 3초를 넘지 않았다.

### 5.4 AI의 역할과 경계

| AI가 하는 일 | AI가 하지 않는 일 |
|---|---|
| 블록 유형 판단: 제목(레벨)·본문·목록(단계)·표·인용 | 글자 추가·삭제·수정·요약·번역 |
| 서식만으로 애매한 경우 판단: 굵은 한 줄 = 소제목인가 강조인가 | 글꼴 크기·줄간격 같은 숫자 계산 (규칙 엔진 담당) |
| 원본 번호("1.1.1", "가.")에서 목록 단계 추론 | 문서 저장·전송·기록 |
| 블록을 대상 문서의 스타일 이름에 연결 (예: "개요 2", "제목 2") | 결과 없이 추측으로 채우기 |

**내용 보존 검사:** AI 출력 블록의 텍스트를 이어 붙인 결과가 입력 텍스트와 공백 정규화 후 정확히 같아야 한다. 다르면 AI 결과를 버리고 규칙 기반 판단으로 대체한다.

**AI를 쓸 수 없을 때:** API 키가 없거나, 네트워크 오류·시간 초과(복사 후 4초)·스키마 오류가 나면 규칙 기반 판단(제목 스타일, 글꼴 크기 순위, 번호 패턴)만으로 맞춘다. 오버레이에는 같은 `양식에 맞춤`을 쓰되, 내부 지표에 판단 방식을 기록한다.

### 5.5 중간 표현 `DocBlock`

박재현·윤승희·이창민의 모듈은 아래 JSON만 주고받는다. 해커톤 0–4h 안에 확정한다.

```json
{
  "source": "winword.exe",
  "blocks": [
    {"type": "heading", "level": 1, "text": "연구 배경"},
    {"type": "paragraph", "text": "본문 내용...", "inline": [{"start": 0, "end": 2, "bold": true}]},
    {"type": "list_item", "depth": 2, "marker": "가.", "text": "세부 항목"},
    {"type": "table", "rows": [["항목", "값"], ["A", "1"]], "col_widths_ratio": [0.3, 0.7]}
  ],
  "decided_by": "llm | rules"
}
```

```json
{
  "target": "hwp.exe",
  "body": {"font": "함초롬바탕", "size_pt": 10, "line_spacing": {"unit": "percent", "value": 160}},
  "headings": [{"level": 1, "style": "개요 1"}, {"level": 2, "style": "개요 2"}],
  "list_markers": ["1.", "가.", "1)", "가)"]
}
```

## 8. 데이터 및 변환 규칙

### 8.1 Markdown·TSV (기본 계층)

v1.0 규칙을 유지한다. 제목·굵게·기울임·목록·인용·코드·파이프 표를 HTML로 변환하고, 원시 HTML은 텍스트로 처리하며, 외부 이미지는 불러오지 않는다. TSV는 직사각형 표만 변환하고, 열 수가 다른 데이터는 기본 붙여넣기로 넘긴다.

### 8.2 구조 판단 규칙 (AI 맞춤 계층)

| 원본 신호 | 우선 판단 | 애매할 때 |
|---|---|---|
| 워드 제목 스타일(Heading 1~3), 한글 개요 스타일 | 해당 레벨 제목 (규칙 확정) | — |
| 본문보다 큰 글자 + 짧은 한 줄 | 제목 후보 | AI가 레벨 판단 |
| 굵은 한 줄 + 본문 크기 | — | AI가 소제목/강조 판단 |
| "1.", "1.1", "가.", "1)", "가)", "○", "-" 시작 | 목록, 기호로 단계 추론 | 기호가 섞이면 AI 판단 |
| HTML `<table>` | 표 (규칙 확정) | — |

### 8.3 대상 서식 변환

| 항목 | 규칙 |
|---|---|
| 본문 글꼴·크기 | 대상 문서 커서 주변 본문 문단 값을 따른다 |
| 줄간격 | 한글 % ↔ 워드 배수·pt 환산. 대상 문서의 값을 우선 사용 |
| 제목 | 대상 문서의 제목/개요 스타일에 연결. 스타일이 없으면 본문 기준 굵게 + 크기 단계 |
| 목록 기호 | 대상이 한글이면 "1. → 가. → 1) → 가)" 공문서 체계, 워드면 대상 문서의 번호 목록 스타일 |
| 표 | 행·열·셀 내용 유지, 열 너비 비율 유지, 대상 문서 표 테두리 따름 (워드 대상 표 맞춤은 P1) |
| 강조 | 굵게·기울임·밑줄만 유지, 원본 색·글꼴은 버림 |

### 8.4 원본 보존

- 클립보드: v1.0과 같이 기존 데이터를 지우거나 교체하지 않는다. AI 맞춤 계층은 클립보드를 쓰지 않고 문서에 직접 삽입한다.
- 문서: 교체는 방금 붙인 범위로만 한정하고, 실행 취소 한 단위로 묶는다. 범위를 확인하지 못하면 교체하지 않는다.
- 글자 내용: 내용 보존 검사를 통과한 결과만 삽입한다.

자동 트리거는 Ctrl+V와 Shift+Insert로 한정한다. 메뉴·리본 붙여넣기는 AI 맞춤을 시작하지 않는다.

| AI 끄고 같은 시험 | 규칙 기반 대체로 결과가 나오고, 원본 손실 없음 |
| 내용 보존 | 맞춤 결과의 글자가 원본과 100% 일치 |
| 붙여넣기 직후 타이핑 | 맞춤 교체가 취소되고 사용자 입력이 보존됨 |
| Ctrl+Z | 한 번에 붙여넣기 이전 상태로 복원 |
| 빠른 연속 복사 A→B | B 기준으로 맞춤, A의 결과로 덮이지 않음 |
| Markdown → 워드 (기본 계층) | 제목·굵게·목록·표 3회 재현 |
| 기존 HTML/Office 내용, 미지원 조합 | ClipBridge를 끈 기본 붙여넣기와 비교해 추가 손실 없음 |
| 오버레이 | 커서·포커스·IME 입력을 방해하지 않음 |

### 11.2 테스트 문서 세트

워드 보고서 10개와 한글 양식·공문서 10개, 총 20개를 고정한다. 각 문서는 제목 2단계 이상, 목록 2단계 이상, 표 1개 이상을 포함한다. 목표: 요소별 맞춤 성공률 90% 이상.

### 11.3 사용자 가치 검증 (근거 데이터)

학과 학생 10명에게 "워드 2쪽 분량(제목·목록·표 포함)을 학교 한글 양식에 맞추기" 과제를 준다. 기본 붙여넣기와 ClipBridge 사용 순서를 절반씩 바꿔 배치하고, 미리 정한 서식 완료 기준까지 걸린 시간과 남은 서식 오류 개수를 잰다.

- **목표:** 작업 시간 중앙값 80% 이상 감소, 서식 오류 개수 70% 이상 감소.
- **목표:** 별도 설명 없이 10명 모두 과제 수행.
- **필수:** 원본 데이터 손실·중복 삽입·글자 변경 0건.

10명 결과는 해커톤 수준의 초기 관찰로 표현한다. 측정 전에는 시간 절감 수치를 성과로 발표하지 않는다.

## 12. 주요 위험과 대응

| 위험 | 사용자 영향 | MVP 대응 |
|---|---|---|
| 붙인 범위를 정확히 찾지 못함 | 엉뚱한 부분이 바뀜 | 범위 텍스트가 복사 텍스트와 일치할 때만 교체, 아니면 무변경 |
| 교체 중 사용자 입력과 충돌 | 사용자가 쓴 글 손실 | Ctrl+V 이후 입력 감지 시 교체 취소, 3초 제한 |
| LLM 지연·오류·잘못된 JSON | 맞춤 실패 | 복사 시점에 미리 호출, 4초 제한, 스키마·내용 보존 검사, 규칙 기반 대체 |
| AI가 글자를 바꿈 | 내용 훼손 | 내용 보존 검사 실패 시 AI 결과 폐기 |
| pyhwpx로 다루지 못하는 서식 | 한글 쪽 품질 저하 | 4요소에 집중, 안 되는 항목은 한글 스타일 적용으로 대체, 범위 기록 |
| COM 호출이 키보드 훅을 지연 | 훅 제거, 자동 동작 중단 | COM·AI는 작업 스레드에서만 실행, 훅은 기록과 깨우기만 |
| 한글·워드 버전 차이 | 시연 PC에서만 동작 | 발표 PC 버전 고정, 사전 준비 기간에 검증 |
| 문서 내용이 외부 AI로 전송된다는 우려 | 신뢰 저하 | 블록 텍스트만 전송, 저장 없음, 오프라인 규칙 기반 동작 명시 |
| 시연 당일 오류 | 점수 손실 | 동일 시나리오 녹화 영상 백업, 안전망(Markdown) 시연 준비 |
| '편의 도구'로 보일 위험 | 임팩트 점수 하락 | 이중 문서 환경, 공문서 규칙 자동 준수, AI 구조 판단을 발표 전면에 |

비밀번호 검사·앱 제외·일시정지를 위험 대응 명목으로 추가하지 않는다.

### 13.1 해커톤 전 사전 준비

| 작업 | 담당 | 완료 기준 |
|---|---|---|
| ClipBridge v1 Windows 검증 (`test_windows_clipboard.py`, 검증표) | 이창민 | 발표 PC에서 통과 기록 |
| pyhwpx 설치·한글 서식 읽기 시험 | 박재현 | 커서 주변 글꼴·줄간격 출력 성공 |

사전 준비에서 v1 Windows 검증이 실패하면, 해커톤 시작 전에 원인을 정리하고 0–4h에 우선 해결한다.

### 13.2 48시간 계획

| 시간 | 작업 | 완료 산출물 |
|---|---|---|
| 0–4h | DocBlock 스키마 확정, 발표 PC 환경 고정, 샘플 선정 | 스키마·샘플 5개·앱 버전표 |
| 4–16h | 클립보드 파싱 2종, 대상 규칙 읽기 2종, 규칙 엔진, AI 구조 판단 각자 개발 | 모듈별 단위 테스트 통과 |
| 16–26h | 호스트 연결, 워드 → 한글 맞춤 삽입과 교체 안전 조건 | 메인 시연 경로 1회 성공 |
| 26–34h | 한글 → 워드, 규칙 기반 대체, 실패 경로 검증 | 양방향 4요소 결과표 |
| 34–42h | 사용자 실험 10명, 오버레이 다듬기, 발표 자료 | 실험 수치·시연 자료 |

**관문:** 26h까지 워드 → 한글 메인 경로가 1회도 성공하지 못하면, 표를 P1로 내리고 제목·본문·목록에 집중한다. 34h까지 실패하면 기본 계층(Markdown)과 규칙 기반 맞춤으로 시연을 구성한다.

### 13.3 3분 시연

1. **0:00–0:30 문제:** 워드 보고서를 학교 한글 양식에 그냥 붙여 서식이 깨지는 화면.
2. **0:30–1:30 해결:** ClipBridge 실행 상태에서 같은 내용을 붙이면, 평소처럼 붙은 뒤 양식 규칙대로 바뀌는 화면. 나란히 비교, "손으로 N분 → 3초" 타이머.
3. **1:30–2:10 반대 방향:** 한글 공문서 항목을 워드에 붙여 "가. / 1)"이 워드 번호 스타일로 바뀌는 화면.
4. **2:10–2:30 안전:** 붙여넣기 직후 타이핑하면 교체가 취소되고, Ctrl+Z 한 번으로 복원되는 모습. AI 없이도 규칙 기반으로 동작함을 설명.
5. **2:30–3:00 근거와 비전:** 10명 실험 수치, 구글 독스·노션·PPT로 넓히는 "어디서 복사하든 붙일 곳에 맞게" 비전.

## 14. MVP 완료 조건

- [ ] 실행 후 별도 설정이나 버튼 없이 한글↔워드 맞춤 붙여넣기가 동작한다.
- [ ] 워드 → 한글 4요소, 한글 → 워드 3요소를 발표 PC에서 3회씩 재현했다.
- [ ] AI를 끈 상태에서도 규칙 기반 맞춤과 기본 계층이 동작한다.
- [ ] 맞춤 결과의 글자가 원본과 100% 일치한다.
- [ ] 붙여넣기 직후 입력 시 교체 취소, Ctrl+Z 복원을 검증했다.
- [ ] 원본 유지·최신 복사 우선·실패 시 기본 동작 시험을 통과했다.
- [ ] 오버레이가 포커스를 빼앗지 않고 자동으로 사라진다.
- [ ] 비밀번호 검사·앱 제외·일시정지·설정 화면이 없다.
- [ ] 발표에 쓰는 성능·시간 절감 수치는 실제 측정값이다.

원본 손실·입력 누락·중복 삽입·글자 변경·사용자 입력 덮어쓰기는 출시를 막는 결함으로 취급한다.

**v1 코드 재사용 방침**

- `host.py`의 키보드 훅은 그대로 "관찰만" 하는 구조를 유지한다. AI 맞춤 계층은 훅에서 붙여넣기 시각과 대상만 넘겨받고, 문서 작업은 별도 작업 스레드에서 한다.
- `transaction.py`의 "최신 복사 sequence 확인" 원칙을 AI 결과에도 적용한다(5.3 조건 2).
- `ui.py` 오버레이에 상태 문구 4종을 추가한다.
