# Windows 검증표 (#24)

**하는 일:** 발표 PC에서 복사해서 붙여 보고, 잘 붙었는지 눈으로 보고, ✅ 또는 ❌를 적는다. 항목마다 3번씩 (PRD 9.1). 마지막에 성능을 재서 적는다.

- ✅ UP을 껐을 때보다 깔끔하게 붙음 (Word·통과 항목은 UP을 껐을 때와 같으면 ✅)
- ❌ 안 바뀌었거나 더 이상하게 붙음 → 스크린샷을 `docs/qa/windows/<번호>-<회차>.png`로 저장
- ⏳ 아직 만들지 않은 기능이라 건너뜀

## 시작 전에 (한 번만)

1. 앱을 터미널에서 켜고 로그를 파일로도 남긴다 (저장소 루트).
   ```powershell
   dotnet run -c Release --project src/ClipBridge.Windows -- --log up.log
   ```
   첫 줄에 `log file=C:\...\up.log`처럼 저장 위치가 나온다. 같은 파일에 계속 덧붙이므로, 새로 재려면 UP을 끄고 파일을 지운 뒤 다시 켠다.
   배포용 실행 파일도 같다: `& ".\Unbroken Paste.exe" --log up.log`
2. 붙여넣을 때마다 이런 줄이 나온다.
   ```text
   10:21:07.115 [paste] paste key=Ctrl+V target=Hangul app=Hwp.exe converter=C1 plan=WriteResult elapsed=1.8ms
   ```
   - `target=` UP이 알아본 붙일 곳 (Hangul·Notion·Word·Excel·Other)
   - `converter=` 쓴 변환기. 아래 표의 "로그" 칸과 같으면 맞게 동작한 것
   - `elapsed=` 붙여넣기 순간 UP이 쓴 시간 (NFR-03)
3. 트레이 슬라임 → Markdown 처리가 **서식 적용 (기본)**, AI 검증이 **켜기 (기본)**인지 확인
4. 아래 칸 채우기 (버전은 각 앱의 도움말 → 정보, 또는 파일 속성 → 자세히)

## 8. 성능 측정

## 10. 시연 구분

- **실제 앱 시연:** 발표 PC에서 `Unbroken Paste.exe`를 켜고 실제 한글·Notion·Word에 붙이는 것.
- **오프라인 시뮬레이션:** 저장한 샘플·스크린샷·녹화로 보여 주는 것. 화면에 "시뮬레이션"이라고 표시한다.
- 성능·시간 절감 수치는 8번에서 잰 값만 쓴다. 9.2 사용자 시험을 하기 전에는 시간 절감을 성과로 말하지 않는다.

## 바로 이슈로 만들 문제

아래가 한 번이라도 나오면 스크린샷과 로그 줄을 붙여 이슈를 만든다 (출시를 막는 결함, PRD 11).

- 복사한 내용이 사라지거나 일부가 빠짐
- 같은 내용이 두 번 붙음
- 엉뚱한 창으로 커서·포커스가 넘어감
- 다른 앱용으로 바꾼 결과가 붙음 (예: Notion에 한글용 결과)
- 로그 `elapsed=`가 50ms를 넘음
